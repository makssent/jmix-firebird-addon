# Installation and configuration

This guide configures a Jmix application to use Firebird as its primary data store. For the
supported Jmix, add-on, Firebird, and Java versions, see the
[compatibility table](../README.md#compatibility).

## Prerequisites

Before starting, prepare:

- a running Firebird server;
- an empty database created before the first application start;
- a database user allowed to create and modify schema objects (by default, you can use `SYSDBA` with
  the password `masterkey`).

## Connecting Firebird to the application

### Gradle dependencies

Add the starter and Jaybird to the `dependencies` block in the application's `build.gradle`:

```groovy
dependencies {
    implementation 'io.github.makssent:jmix-firebird-starter:3.0.1'
    runtimeOnly 'org.firebirdsql.jdbc:jaybird:6.0.5'
}
```

The starter includes the core `jmix-firebird` module. Jaybird is the JDBC driver used to connect to
the database.

Reload the Gradle project after changing the dependencies.

### Datasource configuration

Replace the main datasource settings in `src/main/resources/application.properties` with the
connection to the prepared Firebird database:

```properties
main.datasource.url=jdbc:firebird://localhost:3050//path/to/application.fdb?encoding=UTF8
main.datasource.username=your_username
main.datasource.password=your_password
main.datasource.driver-class-name=org.firebirdsql.jdbc.FBDriver

jmix.data.dbms-type=firebird
```

If you did not change the default administrator credentials when installing Firebird, you can use
`sysdba` as the username and `masterkey` as the password.

Replace `/path/to/application.fdb` with the path to your database.

The `jmix.data.dbms-type=firebird` property is required because Jmix does not automatically detect
Firebird from JDBC metadata.

Keep credentials outside version control for real deployments. The values above are placeholders,
not recommended production credentials.

### Liquibase configuration

Add the add-on changelog to the root `changelog.xml` and place it before the existing Jmix module
and application includes:

```xml
<include file="/io/github/makssent/jmix/firebird/liquibase/changelog.xml"/>

<include file="/io/jmix/data/liquibase/changelog.xml"/>
<!-- Other Jmix module changelogs -->
<!-- Application changelogs -->
```

The order is required. The add-on changelog declares Firebird values for Liquibase properties used
by subsequent scripts.

Review the application changelogs before the first Firebird start:

1. Use `${uuid.type}` instead of a literal `UUID` type for UUID columns:

   ```xml
   <column name="ID" type="${uuid.type}">
       <constraints primaryKey="true" nullable="false"/>
   </column>
   ```

2. If an existing changeset has a `dbms` allowlist, add `firebird` to that list:

   ```xml
   <insert tableName="USER_" dbms="postgresql, mssql, hsqldb, firebird">
   ```

   This commonly applies to the initial administrator and role-assignment inserts generated by a
   Jmix project template.

## Conclusion

After completing these steps, you can run the application with Firebird as its primary database.
If errors, limitations, or compatibility questions arise during startup or later use, see
[limitations and troubleshooting](limitations-and-troubleshooting.md).
