# Firebird add-on for Jmix

[English](README.md) | [Russian](README_ru.md)

The add-on enables Jmix applications to use Firebird as the primary data store.

> [!IMPORTANT]
> For Firebird projects, Jmix Studio Run Action and automatic Liquibase changelog generation for
> model changes are unavailable. See
> [limitations and troubleshooting](docs/limitations-and-troubleshooting.md) for details.

## Compatibility

| Jmix | Add-on | Firebird |
| --- | --- | --- |
| 3.0.x | `3.0.1` | 4.0+ |

The first two add-on version components identify the supported Jmix line. The last component
identifies the add-on release within that line.

## Installation and configuration

You can install the add-on from [Jmix Marketplace](https://www.jmix.io/marketplace/firebird-db/)
or connect it manually as described below.

<details>
<summary>Manual installation</summary>

For manual installation, add the starter to the `dependencies` block in the application's
`build.gradle`:

```groovy
dependencies {
    implementation 'io.github.makssent:jmix-firebird-starter:3.0.1'
}
```

</details>

### 1. Prepare the database

Prepare a running Firebird server and create an empty database before the first application start.
The database user must be allowed to connect and create and modify schema objects.

### 2. Configure Gradle dependencies

Add Jaybird to the `dependencies` block in the application's `build.gradle`.
Jaybird is the JDBC driver used to connect to Firebird and must be added separately:

```groovy
runtimeOnly 'org.firebirdsql.jdbc:jaybird:6.0.5'
```

Reload the Gradle project after changing the dependencies.

### 3. Configure the datasource and Jmix

Replace the main datasource settings in `src/main/resources/application.properties` with the
connection to the prepared Firebird database:

```properties
main.datasource.url=jdbc:firebird://localhost:3050//path/to/application.fdb?encoding=UTF8
main.datasource.username=your_username
main.datasource.password=your_password
main.datasource.driver-class-name=org.firebirdsql.jdbc.FBDriver

jmix.data.dbms-type=firebird
```

Replace the host, port, database path, and credentials with your values. The database path is
resolved on the Firebird server, not on the application host.

If you did not change the default administrator credentials when installing Firebird, you can use
`sysdba` as the username and `masterkey` as the password.

The `jmix.data.dbms-type=firebird` property is required because Jmix does not automatically detect
Firebird from JDBC metadata.

### 4. Configure Liquibase

Include the add-on changelog in the root `changelog.xml` before all Jmix module and application
changelog includes. If the include is already present, check its position instead of adding it again:

```xml
<include file="/io/github/makssent/jmix/firebird/liquibase/changelog.xml"/>

<include file="/io/jmix/data/liquibase/changelog.xml"/>
<!-- Other Jmix module changelogs -->
<!-- Application changelogs -->
```

The add-on changelog declares Firebird values for Liquibase properties used by the following
changelogs, so this include must precede them.

Before the first Firebird start, adapt the application changelogs:

1. Use `${uuid.type}` instead of a literal `UUID` type for UUID columns:

   ```xml
   <column name="ID" type="${uuid.type}">
       <constraints primaryKey="true" nullable="false"/>
   </column>
   ```

2. Add `firebird` to `dbms` allowlists for changes that must run on Firebird. In particular, check
   the initial administrator and role-assignment inserts generated by the Jmix project template:

   ```xml
   <insert tableName="USER_" dbms="postgresql, mssql, hsqldb, firebird">
   ```

### 5. Start the application

Run the application from the command line, since Jmix Studio Run Action is unavailable for
Firebird projects:

```bash
./gradlew bootRun
```

After changing the entity model, create and include Liquibase changesets manually. Studio cannot
generate them automatically for Firebird. For known library compatibility issues and startup
errors, see [limitations and troubleshooting](docs/limitations-and-troubleshooting.md).
